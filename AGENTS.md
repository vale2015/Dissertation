# Project improvement tracking

For every improvement to this project, read `docs/IMPROVEMENT_TRACKER.md` before starting work. Treat it as the persistent backlog: use its numbered order unless the user chooses another item, and add new improvements there before implementing them. Update the backlog in the same work session whenever an item is finished, recording what was implemented and verified. Mark it Done only when its acceptance criteria are met; otherwise keep the accurate Partial, Verify release, or Open status. Keep Git, Supabase, and Vercel status distinct. Do not start the next backlog item without updating the one just worked on.

The user asked to see the proposed changes before commits. Explain the implementation and any incomplete verification before committing or pushing improvement work.
